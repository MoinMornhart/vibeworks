Installation

VibeWorks läuft selbst gehostet. Am einfachsten ist ein Proxmox-VE-Container, der mit einem einzigen Befehl entsteht.

Schnellstart auf Proxmox VE 8/9

In der Shell des Proxmox-Hosts (als root) ausführen:

bash -c "$(curl -fsSL https://raw.githubusercontent.com/MoinMornhart/vibeworks/main/install/proxmox.sh)"

Der Installer prüft den Host, fragt nach Standard oder Erweitert, legt einen unprivilegierten Debian-Container an, installiert darin Node.js, PostgreSQL und VibeWorks und richtet das Auto-Update ein. Am Ende zeigt er die Adresse an, zum Beispiel http://192.168.1.50:3000.

EinstellungStandard
SystemDebian 13 (sonst 12), unprivilegiert
CPU / RAM2 Kerne / 3 GB (der Build braucht viel Speicher)
Festplatte10 GB
Netzwerkvmbr0, DHCP

Im Modus Erweitert lässt sich alles einzeln einstellen: Container-ID, Hostname, Ressourcen, statische IP, VLAN, Storage und ein Root-Passwort.

Demo-Instanz

Im Menü Demo-Instanz wählen (oder VIBEWORKS_DEMO=1 voranstellen): VibeWorks legt dann selbst Beispielprojekte an, Besucher kommen mit „Demo ansehen“ ohne Passwort hinein, alles ist schreibgeschützt, und jede Nacht beginnt die Demo von vorn. Zurückgesetzt wird nur, solange die Instanz ausschließlich das Demo-Konto kennt – eine Instanz mit echten Konten bleibt unangetastet.

Ohne Proxmox (Debian 12/13, Ubuntu 24.04)

apt-get update && apt-get install -y curl curl -fsSL https://raw.githubusercontent.com/MoinMornhart/vibeworks/main/install/vibeworks-install.sh | bash

Das Skript lässt sich gefahrlos erneut ausführen – ein zweiter Lauf repariert die Installation, ohne Daten zu überschreiben. Die Einstellungen stehen in /opt/vibeworks/shared/.env.

Updates

Alle 15 Minuten schaut der Server selbst nach neuen Versionen. Jede Version wird in einem eigenen Ordner gebaut; umgeschaltet wird erst, wenn der Build klappt und die App danach gesund antwortet. Vor jeder Datenbank-Migration entsteht ein Backup, und schlägt der Health-Check fehl, geht es automatisch zurück auf die vorige Version.

BefehlWirkung
updateNeueste Version installieren (fragt vorher)
update --statusVersion, Releases, Auto-Update, Dienst
update --rollbackZurück zur vorherigen Version
update --auto-off / --auto-onAutomatische Updates aus- bzw. einschalten
update --domain <adresse>Adresse (APP_URL) ändern und neu starten

Auf dem Proxmox-Host richtet der Installer zusätzlich den Befehl vibeworks ein (Kurzform update): status, update, rollback, domain, logs, shell, repair – ohne erst in den Container zu wechseln. Im Admin-Bereich der App gibt es außerdem den Knopf „Neuestes Update installieren“.

Backups

Datenbank-Sicherungen liegen unter /opt/vibeworks/shared/data/backups/ (die letzten 10), Uploads unter /opt/vibeworks/shared/data/uploads/. Ein Proxmox-Backup des ganzen Containers lohnt sich zusätzlich. Unter Mein Konto → Daten kannst du deine Projekte außerdem als JSON exportieren.

HTTPS und Passkeys

Passkeys funktionieren nur über HTTPS. Setze einen Reverse Proxy mit Zertifikat davor, zum Beispiel Caddy:

vibeworks.example.de { reverse_proxy 192.168.1.50:3000 }

Danach die neue Adresse eintragen: vibeworks domain https://vibeworks.example.de auf dem Host.
